- No destructive operation is run by this plan: no prod data deleted, no S3 expiration of existing data, CSP report-only. The deletion tool is for the owner.
- Facts on 2026-10-08: 15 user-related columns, 11 FKs to `users` (7 CASCADE, 4 NO ACTION) + audit columns `*_by_user_id`; one Athena workgroup `beatport-prod-analytics` (enforce off, no cutoff; largest recent scan 267 MB); raw bucket versioned without lifecycle; CloudFront without a response-headers policy; `vendor_track_map.match_type` records how Spotify matches were made; auto-ingest's 11:01 UTC scheduled run failed once on a paused Aurora and succeeded on the Lambda retry (each such run fires the errors alarm).
- Worktree `../clouder-core-p2`, branch `chore/p2-senior`; `$VENV=<repo>/.venv/bin`; Conventional Commits, no AI attribution; `git restore graphify-out` before commits; CI must stay green (ruff, mypy, coverage ≥ 80 %, locks, route consistency).

## Review Focus

1. User deletion leaves a row behind in a table added later → `test_delete_user_leaves_nothing` introspects `information_schema` for every `*user_id` column and every FK chain from `users`, not a hard-coded list (Task 4).
2. A deleted user's events come back after a dbt full refresh from bronze → silver/gold anti-join the tombstone table; test on DuckDB (Task 4).
3. Moving curation routes breaks a route or a test patch silently → the route-consistency test plus the full integration suite; patch targets move to `curation/deps.py` (Task 3).
4. `enforce_workgroup_configuration = true` breaks the nightly dbt build or the analytics Lambda → both roles already write `athena-results/*` (checked); verify one dbt build and one analytics call after deploy (Task 9).
5. A transient S3 error marks a run FAILED forever → `TransientStorageError` re-raises for SQS retry; test with botocore `SlowDown` / 503 (Task 2).
